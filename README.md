# 任务看板 · Task Dashboard

使用 React 18 + TypeScript（严格模式）+ Tailwind CSS + Zustand 构建的单页任务看板应用。

## 功能特性

- 三列看板（待处理 / 进行中 / 已完成），支持基于 @dnd-kit 的拖拽排序与状态切换（筛选状态下排序不错位）
- 任务增删改查：新建/编辑弹窗、删除二次确认 + 5 秒内可撤销、操作 Toast 提示
- 重复任务：每天/每周/每月自动生成下一周期任务（顺延到**下一个尚未过去的周期**，逾期很久才完成也不会生成立即逾期的副本；支持月末截断）；取消完成原任务时自动回收刚生成且尚未被触碰的副本
- 任务归档：归档到「已归档」区，不参与统计与提醒，可随时恢复
- 日历视图：月历展示任务（按截止/开始日归位），点击空白日期快速新建（预填当天）、点击任务直接编辑
- 番茄钟专注：任务卡片一键开始 15/25/45 分钟专注，支持暂停/继续/结束，完成时系统通知并可一键标记任务完成（刷新页面计时不丢）
- 键盘快捷键：N 新建、/ 搜索、1-4 切换视图、D 切换深浅色、? 查看帮助
- 组合筛选与搜索：按标题模糊搜索，按优先级、状态筛选
- 未完成任务定时提醒系统：桌面通知 + 应用内横幅，支持频率/时间/静默时段设置（每日/每周/每月按自然周期判定）
- 每日习惯：勾选完成、连续天数、补记历史日期、归档暂停（保留完成记录）
- 统计视图：任务状态分布、近 7 天完成趋势（按**实际完成时间** `completedAt` 统计）、习惯 12 周热力图与本周完成率
- 数据导出/导入备份（JSON，含任务、习惯与全部设置；导入时**弹窗选择方式**：合并导入保留现有数据仅追加新增项，覆盖导入整体替换并二次确认，提醒设置与主题仅随覆盖导入改变）
- 启动时每日一次的未完成清单弹窗（支持「今天不再提醒」）——**在云端同步/合并完成后才计算**，多设备下不会基于过期本地数据误报
- 云端同步：本地先行写入 + 离线队列，断网也能正常操作，联网后自动补同步
- 响应式布局（移动端折叠为列表）与深色/浅色模式
- 弹窗统一支持 ESC 关闭、焦点管理与无障碍语义

## 启动方式

### 一键启动（推荐）

Windows 下**双击根目录的 `启动看板.cmd`** 即可进入启动菜单：

| 菜单项 | 说明 |
| --- | --- |
| 1 开发模式 | Vite 热更新调试；关闭所有页面后服务自动停止，Ctrl+C 也可随时停止 |
| 2 生产模式 | `tsc` 类型检查 + `vite build` 构建后，由内置零依赖静态服务器**常驻后台**（默认 http://127.0.0.1:4173 ），自动打开浏览器 |
| 3 仅启动服务 | 跳过构建，直接托管现有 `dist` |
| 4 停止后台服务 | 停止常驻服务并清理运行状态 |
| 5 重新安装依赖 | `npm install` |
| 6 打开应用页面 | 自动探测运行中的服务并打开浏览器 |
| 7 创建桌面快捷方式 | 在桌面生成 `任务看板.lnk` |

首次运行会自动检测环境：未安装 Node.js 或版本低于 18 时给出指引；`node_modules` 缺失时自动安装依赖。

也支持命令行直接指定模式：`启动看板.cmd [dev|prod|serve|stop|install|open|shortcut]`，可加 `-NoPause`（不等待按键）、`-NoOpen`（不自动打开浏览器）开关。

后台服务的运行状态保存在 `.run/server.json`，日志在 `logs/server.out.log` 与 `logs/server.err.log`（均已在 .gitignore 中忽略）。

### npm 命令

```bash
npm install
npm run dev       # 启动开发服务器
npm run build     # 类型检查 + 生产构建
npm run test      # 单元测试（vitest，覆盖 utils/ 与 lib/ 纯逻辑）
npm run start     # 托管 dist（等价 node scripts/server.mjs）
npm run serve     # 同上（别名）
npm run preview   # 预览生产构建
```

## 目录结构

```
启动看板.cmd      # Windows 一键启动入口
scripts/          # start.ps1 启动器 + server.mjs 生产静态服务器
src/
  components/   # UI 组件
  store/        # Zustand 状态（任务 + 习惯 + 番茄钟 + Toast）
  types/        # TypeScript 类型定义
  utils/        # notificationHelper / reminderScheduler / date / filter / backup ...
  hooks/        # useReminder（轮询逻辑封装）
  lib/          # cloud.ts 云端接入 / syncQueue.ts 离线写队列 / merge.ts 冲突合并 / space.ts 空间密钥
  test/         # 测试环境桩（node 下补 window/localStorage）
```

> 提醒系统说明：应用每分钟轮询一次；「每日/每周/每月」按自然日、自然周（周一为起点）、自然月判定，同一周期内只触发一次（防重复）；
> 页面从后台切回前台（visibilitychange）时会立即补检一次。

## 云端同步

### 数据流

所有写操作都是**本地先行**：先更新本地 state，再把变更放进离线队列（`lib/syncQueue.ts`），由后台在 800ms 防抖后补推云端。

| 场景 | 行为 |
| --- | --- |
| 未配置 `VITE_CLOUDBASE_ENV` | 纯本地模式，队列不启用，行为与改造前一致 |
| 已配置但断网 | 操作**照常生效**并进入待同步队列（右上角云图标出现提示点，页面顶部显示待同步条数），联网或回到前台后自动补推；启动时若处于离线，恢复连接后会自动补一次「拉取 + 合并」 |
| 初始化失败 | 指数退避重试（3s → 60s），**不会**每次操作都重新发起匿名登录并卡一次网络超时 |
| 导入备份 | 全量数据入队补推，失败也只是排队，不再需要重新导入 |

队列持久化在 localStorage（`task-dashboard-sync-queue`），刷新/关闭页面不丢；同一目标的多次修改会合并成一条，队列长度有上限。切换空间密钥时旧队列会被自动丢弃，避免把旧空间数据写进新空间。

### 多设备冲突合并（last-write-wins）

启动时先拉取云端快照，再与本地数据按规则合并（`lib/merge.ts`），**不再全量覆盖**：

1. 同一 `id` 双方都有 → 取 `updatedAt` 较大者，本地较新则同时回推云端；
2. 本地独有的任务：在离线队列里（离线期间的改动）保留并补推；云端整体为空（首次迁移）或本设备从未成功同步过（首次配置云端/老版本升级）保留并补推；否则视为「其他设备已删除」而丢弃；
3. 云端独有的条目 → 采用云端版本；
4. 离线队列里的删除（tombstone）优先级最高；
5. 打卡记录按日期取并集，队列中的日期以队列为准；
6. 提醒设置与主题：本地有未同步改动则以本地为准，否则以云端为准（云端是权威源）。

启动清单弹窗与启动通知严格在「同步 + 合并完成」之后才计算，多设备场景不会推送过期清单。

### 云端安全（重要）

- `VITE_CLOUDBASE_ENV` 会被打进前端 bundle，**任何人都能看到**，它不是秘密。
- 匿名登录的 uid 每台设备独立，因此 `owner` 字段只作为写入归属记录，**不能用于过滤**（过滤会导致换设备读不到数据）。
- 应用提供「空间密钥」做**应用层逻辑隔离**：密钥只保存在各设备的 localStorage，不进入 bundle；同密钥设备共享数据，不同密钥之间互相看不到对方数据（云端文档 `_id` 加空间前缀 + `space` 字段过滤）。
- 逻辑隔离不等于授权。绕过本应用直接调用 CloudBase SDK 仍可能读到集合内的数据。**真正的访问控制必须依靠云开发安全规则**：
  - 单人使用：把集合权限设为「仅创建者可读写」（`{"read": "doc._openid == auth.openid", "write": "doc._openid == auth.openid"}`）；
  - 多人共享：为集合设置「所有用户可读写」时，请务必配合空间密钥，并知悉该权限下数据对任何已认证用户可读；
  - 更高要求：接入真实登录（微信登录 / 用户名密码 / 自定义登录）后，用 `auth.uid` 维度下发规则。

## 已知行为

- 删除任务的 5 秒撤销登记会写入 localStorage：确认删除后即使立刻刷新页面，删除也会在下次启动时落地（撤销窗口内的反悔请在 5 秒内点击 Toast 的「撤销」）。
- 重复任务完成后的副本日期顺延到「下一个尚未过去的周期」，不会补生成中间所有周期（只生成一个副本）。
- 取消完成一个重复任务时，会连带删除**由它自动生成、且至今未被触碰**的那一个副本（副本带 `repeatOf` 溯源；「未被触碰」= 仍为「待处理」且 `updatedAt === createdAt`），让「误点完成 → 取消完成」精确回到操作前的状态。若副本已经被拖动、自动开始或编辑过，则保留不动，并在提示里说明。
- 任务的 `updatedAt` 是**单调递增**的：同一毫秒内的连续改动也严格递增。这既让多设备 last-write-wins 合并有确定顺序，也让「副本是否被触碰过」可以用 `updatedAt === createdAt` 可靠判定。
- 统计的完成时间对旧数据（没有 `completedAt` 字段）回退为 `updatedAt` 近似值。
